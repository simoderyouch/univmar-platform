PHASE 15 — REMNANTS / OFFCUTS

Goal
Keep reusable stone that remains after cutting visible, traceable, and available to allocate to a later project.

Included
- Individual remnant record linked to its parent slab.
- Remnant number, dimensions, calculated m², photo, cutting notes, material, variant, lot/bundle, and warehouse location.
- Lifecycle: AVAILABLE, HELD, RESERVED, CONSUMED, DAMAGED.
- Gallery and detail workspace designed for irregular physical pieces rather than aggregate inventory.
- Exact reuse reservation: only compatible open order lines appear, with server validation for matching variant and reserved-area capacity.
- Order cancellation releases selected remnants; final delivery consumes them.
- Automated integration test covering creation, exact reservation, and automatic release on order cancellation.

Main API
GET  /api/v1/remnants
POST /api/v1/remnants
GET  /api/v1/remnants/{id}
POST /api/v1/remnants/{id}/hold
POST /api/v1/remnants/{id}/reserve     { orderItemId }
POST /api/v1/remnants/{id}/release
POST /api/v1/remnants/{id}/damage

Workflow
1. A slab is cut for a job.
2. Register every reusable remaining piece against the source slab.
3. Record its actual dimensions, location, photo, and notes.
4. Search the recovered-stone gallery when pricing a new project.
5. Reserve the exact offcut to prevent it being allocated twice.

Not included
- Cut optimization or nesting.
- Automated inventory m² consumption from fabrication; this belongs to Phase 16 fabrication operations.
